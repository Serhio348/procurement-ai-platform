**Статус:** реализовано и проверено. `npm run verify` проходит полностью.

## 1. Цель

Создать каркас монорепозитория и те два-три пакета, на которые опирается всё остальное: общие контракты, чистая доменная логика и структурное логирование. Прикладных агентов, MCP-серверов и адаптеров площадок на этом этапе нет.

## 2. Архитектурное решение

Монорепозиторий на **npm workspaces** с четырьмя зонами: `packages/*`, `apps/*`, `mcp/*`, `workers/*`. Реализованы три пакета:

| Пакет | Роль | Зависимости |
|---|---|---|
| `@procurement/contracts` | Zod-схемы: идентификаторы, Domain Profile, Intent, Task, Procurement Case, agent I/O, provenance | только `zod` |
| `@procurement/domain` | Чистая логика: расчёт score, разрешение конфликтов правил | только `contracts` |
| `@procurement/observability` | Структурный логгер с correlation ids | без зависимостей |

Слоевые границы проверяются автоматически, а не соблюдаются по договорённости: `dependency-cruiser` и правило ESLint `no-restricted-imports` запрещают доменному слою импортировать БД, HTTP, Playwright, LLM и даже собственный логгер.

## 3. Почему принято это решение

**npm workspaces вместо pnpm.** pnpm на машине разработчика отсутствует, npm 11 умеет workspaces штатно, и это совпадает с инструментами соседнего проекта `osmos-modbus-service` (zod, vitest, tsx, typescript). Один инструмент меньше — одна причина сборки упасть меньше.

**Закрытые перечисления для capabilities и MCP tools.** Список инструментов объявлен как `z.enum`, а не как строка. Опечатка в allow-листе не компилируется, а специалист принципиально не может через UI изобрести новый инструмент. Это кодом закрепляет границу «специалист настраивает — программист добавляет способности».

**Провенанс на уровне типа.** У `Fact.evidenceIds` и `Risk.factIds` стоит `.min(1)`. Факт без источника не проходит валидацию, то есть его физически нельзя сохранить. Это дешевле и надёжнее, чем просить модель «не забывать указывать источник».

**Score считает код.** `computeScore` принимает нормированные компоненты, веса из версионируемой формулы и список рисков. Модель поставляет факты и уверенность, но не вердикт.

**Конфликты не разрешаются молчанием.** Более сильная область побеждает, но перекрытые правила возвращаются в поле `overridden` и остаются видимыми. Два равных по силе противоречащих правила не разрешаются «по свежести» — поднимается `needs_human`.

**Логгер без внешних зависимостей.** Приёмник записей внедряется параметром, поэтому логи тестируются как обычные данные. Редакция секретов встроена: `token`, `api_key`, `authorization` и подобные вырезаются на любой глубине вложенности.

- `packages/contracts/src/scoring.ts` — пороги упрощены до `review` и `accept`. Прежний третий порог `reject` не нёс отдельного смысла: всё, что ниже `review`, и так отклоняется. Добавлена проверка `accept >= review`.

## 11. Tests

38 тестов, 5 файлов. Проверяются инварианты, а не тавтологии:

| Область | Что проверено |
|---|---|
| Провенанс | факт без evidence и риск без фактов отклоняются |
| Domain Profile | минимальная форма из UI дополняется умолчаниями; невалидный slug отклоняется |
| Иерархия политик | системная политика не перекрывается задачей; перекрытые правила возвращаются, а не исчезают |
| Конфликты | равные по силе противоречия эскалируются, а не решаются по свежести; `30` и `"30"` считаются разными |
| Независимость задач | «водоподготовка» и «насосы» сосуществуют; конфликт по одному ключу не рушит остальные |
| Детерминизм | результат не зависит от порядка входных правил |
| Score | веса применяются; штрафы за риски вычитаются; оценка не уходит ниже нуля |
| Вердикт | низкая уверенность эскалирует даже при оценке 100 |
| Компоненты | отсутствующие данные помечаются как `missing`, а не молча считаются нулём |
| Логгер | correlation ids наследуются в child; секреты вырезаются на любой глубине; Error сериализуется |

### Гео-блокировка — уточнение к этапу 0

Проверено вживую 25.08.2026 с машины разработчика:

- Внешний IP — `79.19.66.8`, Италия, Telecom Italia.
- `goszakupki.by` — DNS отдаёт `95.130.86.3`, но TCP не устанавливается ни на 443, ни на 80.
- `icetrade.by` — отвечает `403` с текстом «Доступ к сайту ограничен для пользователей из вашего региона. Если вы используете VPN, попробуйте отключить его».
- `google.com` — доступен, то есть сеть исправна.

**Вывод, меняющий оценку риска этапа 0.** Прежняя формулировка «площадка нестабильна» была неточной. Площадка, судя по всему, работает, а недоступна она из-за страны выхода трафика. Отсюда два следствия:

1. Воркеры поиска и скачивания должны исполняться с белорусского адреса. Размещение на произвольном зарубежном облаке не подходит. Это требование к развёртыванию, а не к коду.
2. До переезда разработка ведётся в режиме `PROCUREMENT_SOURCE_MODE=fixture` на сохранённых страницах. Переключение на `live` — одна переменная окружения.

**Актуализация 02.09.2026.** Машина разработки теперь находится в Беларуси.
Предыдущая проверка из Италии остаётся только историей выявления deployment
риска и не описывает текущее окружение. `goszakupki.by`, публичные карточки и
список доступны. Для `/tenders/posted` требуется сначала получить анонимную
cookie-сессию с главной страницы; учётная запись не нужна. Текущее решение
зафиксировано в [`STAGE-4.md`](STAGE-4.md).
