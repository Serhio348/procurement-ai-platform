# Этап 110 — адаптивная вёрстка как основа будущего PWA (R32)

## Проблема

Основной двухпанельный UI был жёстко привязан к десктопу: `.shell` — сетка `220px + 1fr`, `.workspace` — `minmax(280px, 40%) + 1fr`, корень `overflow: hidden`. Существующие media queries перестраивали только вложенные формы (фильтры профиля, колонки кейса), но не каркас. На ширине 320–390px панель деталей и часть списка физически не помещались, а внешняя прокрутка была отключена.

Задача R32 решалась не как разовый CSS-патч, а как основа мобильной версии/PWA: паттерны выбраны так, чтобы их можно было вынести в installable-оболочку без переработки логики.

## Реализация

Один консолидированный блок `@media (max-width: 768px)` в `apps/web/src/styles.css` (конец файла). Десктопная вёрстка выше 768px не изменена.

### 1. Навигация — гибрид «bottom tabs + drawer» (WB/Ozon + Gmail)

Семь разделов не влезают в честные 5 вкладок, поэтому навигация двухслойная:

- **Top bar** (`.shell-topbar`, ~52px + `safe-area-inset-top`): кнопка ☰ 44×44, марка + «Платформа закупок».
- **Bottom tab bar** (`.mobile-tabs`, 5 равных колонок, `safe-area-inset-bottom`): Входящие (бейдж непрочитанных), Закупки, Мои закупки, Профили, «Ещё». Главные разделы — одно касание под большим пальцем.
- **Drawer** — та же `.nav`, но `position: fixed` слева (`width: min(300px, 85vw)`), содержит все разделы + блок пользователя. Открывается из ☰ и «Ещё»; закрывается ✕, backdrop, Esc, свайпом влево и автоматически после выбора раздела. Focus-trap (паттерн `ConfirmToast`), фокус возвращается на ☰, фоновый скролл блокируется, закрытая панель `visibility: hidden` — вне tab-order и скринридера. `prefers-reduced-motion` отключает анимацию.
- Состояние — `navOpen` в `Shell.tsx`; ссылки drawer проходят через `useGuardedClick` и закрывают панель только если навигация не заблокирована несохранённой формой.

### 2. Однопанельный list↔detail

Двухпанельный `.workspace` становится `flex`-колонкой с общей прокруткой — это мобильный паттерн «список → карточка», который переиспользует будущее PWA:

- открытая карточка поднимается **над** списком (`order: -1`), специалист сразу видит её, а не прокручивает список до детали;
- детектор «карточка выбрана» без JS: `ProcurementsApp` помечает выбранную `.detail` классом `is-triage-*`, во `InboxPage` выбранное событие содержит `.inbox-actions` — CSS селекторы `[class*="is-triage-"]` и `:has(.inbox-actions)`;
- пустая деталь («Нет закупок в работе» / «Новых изменений нет») скрыта — на мобильном не занимает экран заглушкой.

`:has()` поддерживается всеми актуальными браузерами (Chrome 105+, Safari 15.4+). Паттерн не зависит от маршрута — работает одинаково в «Закупках» и «Входящих».

### 3. Тач-цели ≥44px

Согласно WCAG 2.5.8 / Apple HIG: ссылки меню, `.inbox-row`, кнопки `.triage-actions`/`.inbox-actions`/`.profile-actions`, `.search-profile`, `.doc-open` — `min-height: 44px`; select фильтра поиска — 40px.

### 4. PWA-готовность документа

`apps/web/index.html`:

- `viewport` получил `viewport-fit=cover` — без него `env(safe-area-inset-*)` всегда ноль;
- `theme-color: #1e2430` — цвет полосы shell, красит статус-бар;
- `mobile-web-app-capable` / `apple-mobile-web-app-capable` + `status-bar-style: black-translucent` — installable-режим без браузерного хрома.

Service worker и manifest — следующий этап; вёрстка и мета уже рассчитаны на standalone-режим.

### 5. Прочие страницы и плавающие элементы

- `.profile-page`, `.admin-workspace`, `.my-procurements`, `.procurement-detail` — отступы 16px вместо 20–24px.
- `.procurement-detail-list` схлопывается в одну колонку (dt/dd друг под другом).
- `.my-procurements-header` переносится, поиск — на всю ширину.
- `.toast` и `.connection-stale` прижаты к низу с `env(safe-area-inset-bottom)` — не перекрываются жестовой зоной; `.service-degraded` стекируется над ними.

## Регрессия

`e2e/responsive.spec.ts` — тот же реальный стек, что и `specialist.spec.ts`:

- на 320/390/768px: `scrollWidth ≤ clientWidth` на разделах «Входящие», «Закупки», «Мои закупки», «Профили»; навигация — полоса ≤90px, ссылки видимы;
- на 390px полный сценарий: профиль → поиск → review-кандидат → клик по строке → `.detail` видима и её `y` меньше `y` `.inbox` (карточка над списком); кнопка действия ≥44px.

`specialist.spec.ts` на десктопном viewport не изменён и зелёный — десктопная двухпанельность сохранена.

## Границы и следующие шаги

- Между 769 и ~1024px layout десктопный: сайдбар 220px + две панели тесные, но умещаются. Промежуточный «планшетный» breakpoint (иконки вместо подписей) — при необходимости.
- Слои выше CSS не менялись: React-компоненты, маршруты и API-контракты идентичны на всех ширинах — это и есть переиспользуемость для PWA.
- Следующий этап PWA: `manifest.webmanifest` + иконки, service worker с offline-каркасом, push-уведомления вместо polling-баннера.
