# Этап 111 — «Очистить всё» во входящих (R62)

## Проблема

Входящие копят десятки событий: новые кандидаты, review-строки, изменения по отслеживаемым. Разбирать каждую по одной — рутина; специалист просил массовую очистку с гарантией «очищенное больше не придёт».

## Семантика

«Очистить всё» = «я всё это видел». Это не удаление кейсов и не отказ от закупок:

| Событие | После очистки |
|---|---|
| Та же строка | Помечена dismissed, персистится, не видна |
| Тот же найденный кандидат при следующем поиске | Тот же `change.id` (`inbox-found:{caseId}`) → duplicate, не воскресает |
| То же изменение от слежения повторно | Тот же `inbox-watch:{caseId}:{kind}:{value}:{dedupeKey}` → duplicate |
| **Новое** изменение по отслеживаемой закупке | Приходит — это другое событие с новым id; очистка не ломает watch |
| «Вообще никогда от этой закупки» | Это «Не нужно» по карточке (корзина), а не очистка inbox |

Дедуп по стабильному `change.id` уже был заложен в `SpecialistCatalog.record` и `#dismissed` (STAGE-87) — массовая очистка переиспользует тот же контур без новой механики.

## Реализация

- **API:** `POST /api/inbox/dismiss-all` — `catalog().dismissMany(все открытые)` + `setDismissedInboxIds` + `persist()` в одной записи; ответ `SpecialistInboxDismissAllResponse { items, dismissed }`. Инкрементальный persist (STAGE-108) пишет только изменившиеся строки.
- **UI:** кнопка «Очистить всё» в `.inbox-toolbar` «Входящих» (видна при непустом списке и подключённом handler) → `ConfirmToast` («N записей будет отмечено как разобранные — те же события повторно не появятся, новые изменения продолжат приходить») → тост «Разобрано N» через `pushNotice`. Busy-состояние «Очищаем…».
- **Проводка:** `api/specialist.ts` `dismissAllInbox()` → `main.tsx` → `SpecialistApp.dismissAllInbox` → `InboxRoute.dismissAll` → `InboxApp.onDismissAll` → `InboxPage`. Без handler'а кнопки нет — страница остаётся чисто презентационной.
- Тач-цель ≥44px в мобильном блоке (R32).

## Регрессии

- `app.test.ts` «clears the whole inbox and a re-posted event does not resurrect»: dismiss-all отдаёт `dismissed = N`, `items: []`; повторный POST того же события → `duplicate`, inbox остаётся пустым.
- `InboxApp.test.tsx`: кнопка открывает confirm, «Отмена» не вызывает handler, «Очистить» вызывает один раз; без handler/строк кнопки нет.

## Связь с PWA/push

Тот же dismissed-контур пойдёт для push-дайджестов: событие, которое специалист разобрал, не должно приходить пушом повторно; новое событие — и inbox-строка, и пуш.
