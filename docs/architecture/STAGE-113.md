# Этап 113 — «Заполнить профиль» по свободному описанию (R64)

## Проблема

Заказчик сообщил: создать профиль трудно — надо придумать поисковые слова и исключения, понять форму целиком. Кнопки-подсказки у каждого поля не решают холодный старт: без контекста модели нечего анализировать.

## Решение

Единая точка входа вместо полевых подсказок: поле «Опишите направление своими словами» + кнопка «Заполнить профиль» над формой.

### Поток

1. `POST /api/profiles/suggest { text }` → модель (`ProfileSuggestPort.draft`) возвращает первый черновик + `probeTerms` (≤3 фразы для проверки).
2. API прогоняет probe-термины через листинг goszakupki.by — `suggestSearch` на **interactive-линии** MCP (кнопка не ждёт фоновую очередь поиска/ingest), `limit: 25` на термин, без чтения карточек.
3. Модель (`refine`) получает текст + черновик + реальные заголовки → подправляет keywords под лексику площадки, добавляет исключения по видимому мусору. Guard: refine не может опустошить keywords первого черновика; без заголовков второй вызов модели не делается.
4. Ответ `SpecialistProfileSuggestResponse { draft, explanation, sampledTitles, grounded }` — **ничего не сохраняется**: специалист правит и жмёт «Сохранить профиль».

### Границы модели

- `SpecialistProfileDraft` — pick из `SpecialistProfileWrite`: только name, purpose, keywords, excludeKeywords, statuses, excludeSingleSource. Фильтры и `watchNewProcurements` модель не трогает.
- Парсинг ответа модели ленивый (`.catch()` на каждое поле): сломанное поле → дефолт, а не 500; статусы фильтруются по enum, списки дедупятся и режутся до 50.
- `503 model_unavailable`, если `LLM_API_KEY` не настроен — кнопка/блок в UI показываются только при подключённом `suggest`-пропе.
- Проб листинга не убивает подсказку: при ошибке источника возвращается черновик по тексту с `grounded: false` и честной подписью.

### UI

- Блок `.profile-assist` над формой; при успехе — зелёная заметка с `explanation` и «Проверено по N реальным объявлениям»; при ошибке — `search-notice` с причиной.
- Применение: название/назначение — только в пустые поля; keywords/excludeKeywords — merge с дедупом; statuses/excludeSingleSource — из черновика. Dirty-флаг включается сам, автосохранения нет.

## Регрессии

- `app.test.ts`: grounded-черновик с реальными заголовками; ungrounded-деградация при падении листинга; 503 без модели.
- `profile-suggest.test.ts`: clamping мусорных полей, отказ от второго вызова без заголовков, запрет пустых keywords.
- `ProfileApp.test.tsx`: заполнение формы без сохранения, видимая ошибка при сбое.

## Следующие шаги (не сделано)

- Подсказка профиля по ссылке-примеру реальной закупки (карточка → термины из предмета/лотов).
- Подсказки исключений по истории отклонённых карточек специалиста.
