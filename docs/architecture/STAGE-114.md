# Этап 114 — PWA-оболочка консоли

## Проблема

Консоль работает только как вкладка браузера: на телефоне её нужно открывать по URL каждый раз, нет установки как приложения и быстрого запуска с домашнего экрана.

## Решение

Минимальная PWA-оболочка без офлайн-режима данных (это отдельный этап — кэширование карточек и inbox без политики консистентности показывало бы специалисту протухшие закупки).

### Что добавлено

- `public/manifest.webmanifest` — `display: standalone`, `start_url: /`, ru-названия, иконки `icon-192`, `icon-512`, `icon-maskable-512` (рисунок повторяет boot-mark из index.html). Chrome показывает «Установить приложение»; iOS — «На экран Домой» через `apple-touch-icon.png`.
- `public/sw.js` — service worker **только для оболочки**:
  - `install`: precache `/`, `/index.html`, manifest, иконка;
  - `fetch`: `/assets/*` (хэшированные, иммутабельные) — cache-first; навигации — network-first с фолбэком на кэшированный `index.html`;
  - **`/api/` никогда не кэшируется** — устаревшие карточки, inbox и решения недопустимы.
- `index.html`: `<link rel="manifest">`, favicon, `apple-touch-icon`.
- `main.tsx`: `navigator.serviceWorker.register("/sw.js")` только в prod-сборке — dev-сервер и тесты не затрагиваются.
- `eslint.config.js`: блок `apps/web/public/sw.js` с serviceworker-глобалами (`self`, `caches`, `fetch`, `URL`).

### Поведение без сети

Оболочка открывается из кэша, `LiveConsole` показывает экран «Нет связи» с кнопкой «Повторить» — данные не подменяются кэшем.

### Замечание по деплою

`/sw.js` должен отдаваться без длинного `Cache-Control`, иначе браузер поздно заметит новую версию воркера. В nginx для `sw.js` достаточно `Cache-Control: no-cache` (etag-ревалидация).

## Регрессии

- `pwa.test.ts`: manifest парсится и содержит обязательные 192/512 raster-иконки и maskable; файлы иконок существуют; index.html линкует manifest и touch-icon; sw.js явно исключает `/api/` из кэша.
