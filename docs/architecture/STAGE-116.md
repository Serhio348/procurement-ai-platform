# Этап 116 — Удаление профиля забирает свои нерешённые карточки

## Проблема

`DELETE /api/profiles/:id` снимал строку профиля и его review-вердикты, но
оставлял связи `workspace_procurement_profiles` и `profileIds` внутри JSON
карточки. На живой базе 54 такие связи висели на профилях, которых уже нет.
53 из этих карточек не имели ни одного живого профиля: `profileIds` с мёртвым
id прятал их от всех существующих направлений (`procurementBelongsToProfile`
не доходит до запасного совпадения по словам, пока массив не пуст).

Общая строка каталога `procurements` при этом одна на все кабинеты. Чистка
не имеет права её удалять: у другого кабинета своя строка `workspace_procurements`
на ту же закупку.

## Решение

Правило одно, в `releaseProfileFromCard`:

- карточка без решения специалиста и без других профилей — удаляется вместе
  со связями и строками входящих этого кабинета;
- есть решение (`triage`, архив или запись в журнале решений) или другой
  профиль — карточка остаётся, профиль и его вердикт снимаются;
- общая строка `procurements` и файлы в хранилище не трогаются;
- удаление фильтруется по `workspace_id`, поэтому чужой кабинет не меняется.

Память процесса забывает такие карточки и не даёт фоновому поиску удалённого
профиля записать их снова. Миграция `0012_release_deleted_profiles` применяет
то же правило к уже накопившимся сиротам.

## Приёмка

- Удаление профиля A в кабинете 1 не меняет карточку той же закупки в кабинете 2.
- Нерешённый review-кандидат только профиля A исчезает и не возвращается после
  перезапуска.
- «Участвую» / «Слежу» / «Не нужно» и архив остаются, уже без этого профиля.
