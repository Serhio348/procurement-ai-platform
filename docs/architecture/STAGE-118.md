# Этап 118 — Сокращение внутри чужого кода не закрывает поиск

## Проблема

Профиль поставки принимал закупки вроде «сертификат ЭТП», «щетка ЩТП» и
«корзина ТПБ» с оценкой 60 и причиной «Совпадает оборудование: ТП». Модель
эти карточки не видела.

`termMatchStrength` уже отличает точное слово от сокращения внутри чужого
кода и прямо называет второе подсказкой, а не доказательством. Дешёвый
классификатор заголовка по этой подсказке ставит `weak` и оставляет
карточку на проверку. Оценка плана поиска смотрела только на `termOccurs`,
а тот считает вложенное сокращение таким же попаданием, как целое слово.
Для профиля поставки это 40 баллов за объект и 20 за подразумеваемую
поставку. Порог уверенного совпадения — 55, поэтому вердикт `match`
записывался кодом, и вызов модели пропускался.

## Решение

`termEvidence` сохраняет три состояния: точное слово или код, который
термин сам начинает (`КТП`, `КТПБ-250`, `Ф-300 ТП`), склонение, и
вложенное сокращение (`ТП` в `ЭТП` / `ЩТП` / `ТПБ`, `КТПБ` в `2БКТПБ`).

Если все найденные объекты — только вложенные, `decisionFor` возвращает
`review`, даже когда сумма баллов уже выше 55. Карточка уходит модели по
уже существующему пути. Причина для специалиста: слово встречается только
внутри чужого кода.

Точный токен по-прежнему закрывает код сам. Вето на работу в голове
заголовка («Монтаж БКТПБ» для профиля поставки) тоже остаётся за кодом:
вложенность объекта не отменяет явный предмет-работу. Профиль работ без
своего глагола по-прежнему отбрасывает голый объект и не зовёт модель на
каждую «ЭТП».

Уже записанные совпадения с оценкой 60 сами не пересчитываются. Их снимет
следующий поиск.

## Приёмка

- «Сертификат ЭТП», «ЩТП-13.04», «ТПБ», «2БКТПБ» и лот «сертификат ЭТП» при
  чистом заголовке — `review`, не `match`, хотя оценка не ниже 55.
- «Ф-300 ТП», «Поставка КТП», «КТПБ-250» — по-прежнему `match` без модели.
- «Монтаж ЭТП» для профиля работ — `review`; «Монтаж ТП» — `match`;
  «Монтаж БКТПБ» для профиля поставки — `veto`.
