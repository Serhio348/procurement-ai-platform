# Этап 119 — Двухбуквенный объект проверяет модель

## Проблема

После этапа 118 сокращение внутри чужого кода («ТП» в «ЭТП») уходит на
проверку. Отдельное «ТП» по-прежнему закрывало поиск само. Так в кабинет
попали реагенты «анализатор Ф-300 ТП» и стеновая панель с маркой «ТП-1»:
для кода это точное слово, для профиля поставки — 60 баллов и вердикт
«подходит».

Привязывать такое слово к «кВ» или «подстанции» нельзя. Следующий профиль
может искать железобетон, и двухбуквенное «ЖБ» там будет таким же спорным
объектом.

Отдельный потолок: за один проход профиля модель вызывалась не больше 50
раз. Хвост записывался во входящие с текстом «лимит проверок исчерпан».

## Решение

Если все найденные объекты профиля — слова из двух букв, вердикт
`review`, даже когда сумма баллов уже выше 55. Карточка уходит модели.
Слово от трёх букв и фраза на той же карточке по-прежнему закрывают поиск
кодом: «КТП», «КТПБ-250», «железобетонные конструкции».

Явный предмет-работа («Монтаж БКТПБ» для профиля поставки) по-прежнему
отклоняет код, без модели.

`DEFAULT_REVIEW_MAX_MODEL_CALLS` поднят с 50 до 500. Счётчик по-прежнему
один на проход одного профиля и в начале следующего прохода нулевой.
Уверенное совпадение и явный отказ лимит не тратят.

## Приёмка

- «Ф-300 ТП», «ТП-1» и «ЖБ-1» — `review`, не `match`.
- «Поставка КТП», «КТПБ-250» и «Поставка железобетонные конструкции» —
  `match` без модели.
- Один проход профиля может вызвать модель до 500 раз.
