# Этап 120 — Общие работы на профиле работ проверяет модель

## Проблема

Запрос `request/3731483` — «Выбор подрядчика для выполнения работ по сетям
электроснабжения 0,4кВ». Площадка отдаёт его по словам профиля монтажа
«электроснабжение» и «сети электроснабжения». Код находил предмет и сразу
ставил вето: в названии нет «монтаж», «пусконаладка» или «СМР», голова
названия — «выполнение работ». Карточка не попадала ни в очередь, ни к модели.

Для профиля поставки такое вето верное: «выбор подрядчика … КТП» — не
поставка. Для профиля работ та же формулировка при уже найденном предмете
ничего не доказывает. Профиль как раз ищет работы, а вид работ в названии
не назван.

## Решение

Если план — `works`, предмет найден в названии, а голова названия только
«работы» или «подрядные работы», вердикт `review`. Карточка уходит модели.
Чужое назначение по-прежнему закрывает код (`discard`). Явный глагол
профиля («Монтаж сетей электроснабжения») по-прежнему закрывает код как
совпадение.

Профиль поставки не затронут: «Выполнение работ по устройству сетей
электроснабжения», «Реконструкция КТП», «Выбор подрядчика на монтаж КТП»
остаются вето без модели. Голый подряд без предмета профиля тоже остаётся
вето.

## Приёмка

- «Выбор подрядчика для выполнения работ по сетям электроснабжения 0,4кВ»
  на профиле работ — `review`, модель вызывается.
- «Выполнение работ по устройству сетей 0,4кВ» узнаёт предмет «сети 0,4 кВ»:
  пробел перед «кВ» не обязателен.
- «Монтаж сетей электроснабжения» на том же профиле — `match` без модели.
- То же название работ на профиле поставки — `irrelevant` без модели.
- «Выполнение работ … для освещения» при исключённом освещении — `discard`.
