# Этап 13 — веб-интерфейс (inbox)

**Статус:** узкая консоль специалиста: слева срочные ChangeEvent, справа
карточка выбранной закупки. Это не чат с моделью и не полный набор экранов
STAGE-0.

---

## 1. Цель

Показать специалисту уже доставленные срочные изменения, чтобы из ленты
открыть закупку: статус, ссылка на площадку, текст diff.

## 2. Архитектурное решение

- `apps/web` — React + TypeScript + Vite.
- Данные — fixture JSON рядом с UI. Zod проверяет форму. Verify и показ не
  требуют PostgreSQL, Notification MCP и Docker.
- В ленту попадают только `change.urgent === true`. Несрочное (в fixture —
  смена цены «бытового щитка») скрыто.
- Текст изменения собирает `compileChangeAlert` из domain: `previous` /
  `current` копируются как есть.
- Меню «Закупки / Профили / Задачи» видно и выключено («скоро»).
- Логина нет. Кнопок «принять / игнорировать» нет. Поля ввода для модели нет.

```text
inbox.fixture.json
  → presentUrgentInbox
  → список слева / карточка справа
```

## 3. Почему именно так

**Сначала inbox.** NotificationAgent уже умеет доставлять; без экрана
специалист это не видит.

**Fixture, не API.** На этапе 12 inbox живёт в памяти MCP-процесса. Отдельный
Fastify + `notification_outbox` — следующий срез, не этот.

**Код рисует diff.** Иначе в карточке появится «аванс 50%» из подписи UI.

**Не чат.** Постановка задачи формой Intent — позже.

## 9. Тесты

- несрочное изменение не попадает в ленту;
- в тексте нет выдуманного аванса;
- клик открывает другую карточку: статус и ссылка площадки;
- нет кнопок принять/игнорировать и нет textbox;
- пустая лента: «Новых изменений нет»;
- пункты «скоро» disabled.

Проверка реализации: `npm run verify` — 204 прошедших теста без площадки,
LLM, Telegram и Docker.

## 10. Риски и ограничения

1. **Нет живого inbox.** Рестарт и NotificationAgent не наполняют этот экран.
2. **Нет списка закупок и редактора профиля.**
3. **Нет HITL-ответов и отчёта** — сознательно отложено.
4. **Desktop.** Узкий телефонный inbox не верстался как основной.

## 11. Критерии приёмки
