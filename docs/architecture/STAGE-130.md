# Этап 130 — Дозревание resume: якорь окна, курсор упавшей линии и is-open

## Проблема

После этапа 129 нативное окно БУТБ стало обрезаться честно (`hasMore`
вместо мёртвого таймаута), но прод показал, что усечённое окно всё равно
не сходилось. Журнал discovery за 12 часов рисовал цикл:

```
проход 1: resumed [gz, butb] → «не ответили: butb» → saved [gz]
проход 2: resumed [gz]       → butb с нуля          → saved [gz, butb]
проход 3: resumed [gz, butb] → «не ответили»        → saved [gz]
проход N: resumed []         → полный рестарт
```

Профиль с ~20 термами на БУТБ требует нескольких ограниченных вызовов
подряд; любой из них мог умереть execution-таймаутом — и окно начиналось
с головы. Корни в коде:

1. **Курсор упавшей линии стирался.** Проход делал
   `scanCursors = { ...page.scanCursors }` — карта токенов целиком
   заменялась ответом текущей страницы. Линия, чей вызов сгорел
   по таймауту, токен не возвращает → её ключ исчезал → следующий
   проход читал её окно с нуля. Водяная метка при этом честно стояла
   (окно непрочитано — правильно), но курсор не двигался: вечный
   пересмотр одной и той же головы.
2. **Внутренний дедлайн не достигал цепочки постбеков.** Одна
   `filteredPage` — это expand → submit → restore → self-heal с
   ретраями; все они слепы к `deadline` вызова. Зависшая цепочка
   убивала вызов целиком по caller-таймауту вместо честного `hasMore`.
3. **`ret` — позиционный курсор.** Он считал отданные строки
   в отсортированном merge-окне; свежие посты, вставшие в голову
   между вызовами, сдвигали абсолютные позиции — голова переотдавалась
   дублем, а удалённые строки превращались в пропуски.
4. **Кэш окна читался только при токене.** `#windows` консультировался
   лишь при `resume !== undefined`: вызов, сгоревший до выдачи курсора,
   оставлял вызывающего без токена — и следующий вызов пересабмичивал
   все термы, хотя частичное окно жило в памяти процесса.
5. **Интерактив и фон делили один бюджет.** Линия карточек не имела
   способа урезать поиск БУТБ: интерактивный native-поиск мог держать
   пайп минутами за кликами.
6. **Мобильный гейт карточки опирался на triage.** CSS
   `.detail:not([class*="is-triage"])` прятал панель: неразобранная
   карточка очереди поиска выбиралась роутом, скролл шёл к ней — а
   панель оставалась `display:none` на ширине ≤768 px.

## Решение

`apps/api/src/app.ts`:

- **`mergePageCursors(cursors, reported)`** — merge вместо замены.
  Ключ удаляется только когда линия *ответила* и не вернула токен
  (окно дочитано до конца). Линия из `failedSources` сохраняет
  прежний токен — таймаут ≠ потеря позиции. Применяется и к первой
  странице, и к каждой continuation-странице прохода.
- **`DISCOVERY_SEARCH_BUDGET_MS = 900_000`** — бюджет retrieval для
  фонового прохода отделён от `options.searchBudgetMs` (последний
  заточен под nginx-таймаут ручного поиска). `fetchProfileHits` принимает
  `retrievalBudgetMs` необязательным параметром; ручной поиск
  не затронут.

`mcp/procurement/src/butb-source.ts`:

- **Дедлайн внутрь постбек-цепочки.** На каждую `filteredPage`
  строится `pageTimeout = AbortSignal.timeout(remaining)`; при
  наличии caller-сигнала — `AbortSignal.any([ctx.signal, pageTimeout])`.
  Отказ по `pageTimeout.aborted` → `hasMore = true`, терм остаётся
  недочитанным, окно кэшируется. Вызов больше не умирает
  execution-таймаутом из-за одной зависшей цепочки.
- **Якорь в курсоре.** `ButbScanCursor.n` для `m:"n"` — registry-номер
  последней отданной строки. Resume вычисляет `skip` как
  `merged.findIndex(anchor) + 1`; якорь, ушедший из реестра, —
  фолбэк на `ret`. Головные вставки между вызовами не сдвигают
  позицию и не переотдают префикс.
- **Кэш безусловно.** `#windows` консультится всегда по fingerprint —
  потерянный токен не обнуляет done-terms: недочитанные термы
  дочитываются, а не перечитываются все. Свежие посты на закрытом
  терме покрываются водяной маржой следующего прохода.

`apps/api/src/procurement-mcp.ts` + `main.ts`:

- `connectProcurementMcp` принимает `envOverrides`, применяемые
  последним слоем поверх `process.env` ребёнка. Интерактивная линия
  получает `BUTB_BY_MAX_SEARCH_MS = BUTB_BY_INTERACTIVE_MAX_SEARCH_MS
  ?? 120000` — интерактивный поиск обрезан бюджетом карточек;
  фоновая линия наследует продовое значение (поднято до 480 с —
  окно профиля сходится за 1–2 вызова). Переменная с префиксом
  `BUTB_BY_` безопасно игнорируется дочерним goszakupki.

`apps/web`:

- `ProcurementsApp` помечает выбранную панель `is-open` в дополнение
  к `is-triage-*`. Мобильный гейт заменён на
  `.detail:not(.is-open):not(:has(.inbox-actions))` — открытая
  неразобранная карточка показывается на телефоне; inbox-маркер
  `.inbox-actions` не задет.

## Что не изменилось

- Честность усечения: `hasMore`/курсор эмитятся ровно когда хвост
  непрочитан; failed-lane ≠ пустая выдача; водяная метка двигается
  только над полностью прочитанным окном.
- Изоляция линий: один stdio-ребёнок на источник на линию,
  `createSourceRoutingCaller` не тронут.
- Семантика здоровья: queue-таймаут пробы — занятость, не сбой
  (этап 129).

## Регрессии

- `butb-source.test.ts` (42 → 45): якорь переживает вставку в голову
  (skip точный, префикс не переотдаётся); дедлайн-аборт внутри
  `filteredPage` возвращает `hasMore` + токен вместо ошибки;
  кэш окна работает и без токена (дочитанный терм не пересабмичен).
- `app.test.ts` (114 → 115): линия, сгоревшая на continuation,
  сохраняет `butb`-токен между проходами — карта не сжимается.
- `ProcurementsApp.test.tsx` (25 → 26): выбранная неразобранная
  карточка получает `is-open` без `is-triage-*`.
- `npm run verify` — зелёный целиком.

## Продовые заметки

- На сервере `BUTB_BY_MAX_SEARCH_MS` поднят 90000 → 480000
  (фоновая линия); интерактив остаётся 120000 через
  `BUTB_BY_INTERACTIVE_MAX_SEARCH_MS` по умолчанию.
- Ожидаемая картина журнала: неполные проходы показывают
  `resumedFrom` == `scanCursors` предыдущего прохода и прогресс
  `termsDone`, а не возврат к `resumed []`.

## Дополнение — позиция внутри недочитанного терма

Прод подтвердил сходимость кандидатов (`ret`: 208 → 404 → 620, якорь в
токене), но `termsDone` застрял на 22 из 24 — и «усечена» в журнале
повторялась каждый проход. Причина: терм «ТП» — сотни строк, больше
бюджета одного вызова; кэш знал только *число* дочитанных термов, поэтому
недочитанный терм каждый вызов перечитывал с первой страницы и никогда
не заканчивался — `hasMore` был вечным.

`ButbNativeWindow` и нативный курсор получили `termIndex`/`nextPage`
(`ti`/`pg` в токене): недочитанный терм продолжает со следующей
непрочитанной страницы. Правило применения: `ti`/`pg` работают только
при живом `#windows` — без кэша кандидатов пропуск головы терма
оставил бы `ret`-срез на сдвинутых позициях и хвост терялся бы;
после рестарта честный resume — полное перечитывание, дедуп на
стороне вызывающего гасит повторы. Регрессия покрыта тестами:
resume продолжает «хвост» со страницы 2, а свежий инстанс без кэша —
как прежде — перечитывает окно целиком.

Отдельно: `stale`-статус линии убран из пользовательского списка
`degraded` — занятая линия честно старит вердикт, но «Сервис работает
не полностью» это не поломка. Плавающие баннеры получили
`pointer-events: none` — наложение больше не глотает тапы по списку.

## Дополнение — доставка обновлений в PWA и иконки

Прод показал, что правильный код может не доезжать до устройства:
навигация в sw.js уже была network-first, но у worker не было
`skipWaiting` — обновлённый SW ждал закрытия всех клиентов, а PWA на
телефоне живёт неделями, поэтому свежий бандл никогда не активировался
и пользователь «не мог перезагрузить приложение».

`sw.js` получил `self.skipWaiting()` в install и версию кэша v2;
`main.tsx` перезагружает страницу один раз по `controllerchange` и
зовёт `registration.update()` при каждом запуске — новый воркер
забирает управление и сам перезагружает оболочку.

Иконки пересобраны full-bleed: фон #1e2430 залит до краёв кадра
(у старых PNG углы и поля были прозрачными — маска адаптивной иконки
лаунчера обнажала их белыми просветами). Maskable-версия держит
рисунок внутри безопасной зоны (~78 % кадра); `any`-иконки и
apple-touch-icon — тот же рисунок на полном поле.
