# Этап 19 — факты поставки и гарантии из Word-ТЗ

**Статус:** дешёвый разбор читает срок поставки и гарантию из ТЗ. «предоплата
до 99,5%» показывается как условие «Аванс: до 99,5%», но не как точка для
оценки. Оценку 0–100 считает только код.

---

## 1. Цель

После этапа 18 Word-ТЗ уже есть как `office_text`. Специалист должен видеть
числа с цитатой: поставка 60 календарных дней, гарантия 60 месяцев — без
вызова модели и без превращения потолка аванса карточки в факт.

## 2. Архитектурное решение

```text
docx → Open XML: соседние <w:t> склеиваются без пробела
     → страница целиком (лимит 100k, не 8k)
     → cheapExtractCommercialClaims (\p{L}, «календарных дней»)
     → keepQuotedClaims
     → assembleCommercialTerms
карточка «предоплата до N%» → commercial.advance_percent_cap (показ «до N%»)
«в размере N%» при «до N%» на странице → не advancePercent
```

- Склейка runs — в `mcp/documents` (знание про Word). Domain по-прежнему
  видит только текст.
- `\w` в JS — латиница. «гарантийный» / «календарных» требуют `\p{L}`.
- Модель не вызывается, если дешёвый разбор уже нашёл цитату.
- Score не считается.

Повторно разобрать Word из `data/blobs` без площадки и без vision:

```text
REFRESH_LIVE_OFFICE=1 npm run capture:live-case
```

## 3. Почему именно так

На `auction/3629820` условия стоят в конце ТЗ. Лимит 8k обрезал блок, а
подмена тегов пробелами давала «6 0» и «Гарантийны й». Regex «N дн» не
видел «60 календарных дней».

«до 99,5%» — потолок, не точка. Тот же процент в договоре как «аванс в
размере 99,5%» при «до 99,5%» на странице тоже не берём.

## 4. Изменения

- Word/PowerPoint: теги в пустую строку, не в пробел; ячейки таблицы — таб;
- лимит текста Office 100k;
- cheap extract: `\p{L}`, календарные/банковские дни, гарантия;
- пропуск аванса-потолка;
- консоль: блок «Коммерческие условия» из ТЗ; заголовок «Текст документов».

## 9. Тесты

- runs «Г»+«лавный» и «6»+«0» → «Главный», «60»;
- «Гарантийный срок не менее 60 месяцев» и «Срок поставки не более 60 календарных дней» → факты;
- «предоплата до 99,5%» и «аванс в размере 99,5%» на той же странице → не аванс;
- compileSpecialistCase показывает 60 дн. / 60 мес. без аванса 99;
- UI рендерит блок коммерческих условий.

## 10. Риски и ограничения

1. Дешёвый разбор по-прежнему узкий: свободный «порядок расчётов» идёт в
   модель, только если regex ничего не нашёл.
2. Старый OLE `.doc` не читается.
3. Если ТЗ и договор дадут разные сроки, поле не выбирается «по дате» —
   конфликт как в этапе 9.
4. OLE-пробелы внутри `<w:t>` (настоящий пробел в XML) остаются.

## 11. Критерии приёмки

- [x] поставка и гарантия из ТЗ — факты с цитатой;
- [x] потолок «до 99,5%» не становится авансом;
- [x] альбомы проекта по-прежнему не OCR-ятся;
- [x] `npm run verify` без живого LLM и без площадки.
