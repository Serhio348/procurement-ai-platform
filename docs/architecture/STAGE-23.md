# Этап 23 — несколько профилей, пустой старт

**Статус:** направлений может быть несколько. Каждое — свои слова и своё
слежение. Стартовый профиль пустой: отрасль не зашита в поля формы.

---

## 1. Цель

Специалист ведёт подстанции и водоподготовку как два профиля, не затирая
один другим. Форма не приносит готовые КТПБ / «электрооборудование».

---

## 2. Архитектурное решение

```text
SpecialistWorkspace.profiles[]
  → GET  /api/profiles
  → POST /api/profiles              # пустой профиль, становится активным
  → DELETE /api/profiles/:id        # нельзя удалить последний
  → POST /api/profiles/:id/activate
  → PUT  /api/profiles/:id
  → POST /api/profiles/:id/watch
Разовый поиск
  → на «Закупках» выбирают профиль, затем
    POST /api/procurements/search   # keywords выбранного профиля
Discovery
  → все профили с watch=true; найденная карточка помечается профилем
Решения
  → по-прежнему глобально по sourceProcurementId
Список закупок
  → только карточки выбранного профиля
```

Один `DomainSearchAgent`. Тема — данные профиля, не отдельный класс.

Старый workspace `{ profile, decisions }` читается и становится
`profiles: […], activeProfileId`. Стоковый seed электрооборудования при
загрузке очищается, чтобы поля снова были пустыми.

---

## 3. Почему именно так

**Список, не overwrite.** Иначе «завтра водоподготовка» стирает сегодняшние
подстанции вместе со слежением.

**Пустой старт.** Seed `electrical_equipment.v1` остаётся для агентов и
fixture-тестов. Консоль его больше не подставляет.

**Watch на профиле.** Слежение независимо. Таймер обходит только включённые.

---

## 4. Изменения

- UI: список `/profiles`, крестик удаления, редактор `/profiles/:id`, «Новый профиль».
