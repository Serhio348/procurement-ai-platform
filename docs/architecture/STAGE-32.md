# Этап 32. Сила совпадения: точное слово против кода

## Цель

Убрать из списка «Закупки» процедуры, где ключевое слово профиля найдено
только внутри чужого кода. Пример: профиль ищет `КТПБ`, площадка вернула
«Реконструкция ВЛ-0,4 кВ от БКТПБ-746» — это строительно-монтажные работы,
а не поставка подстанции, но старый фильтр считал совпадение полным.

## Проблема

`termMatches` возвращал `boolean`. Для «кодоподобных» токенов (с цифрой,
дефисом или заглавными) он разрешал подстроку, чтобы ловить модели вроде
`НКУ-0,4` или `2БКТПБ`. Но тот же путь пропускал `КТПБ` внутри `БКТПБ-746`
и `КТП` внутри `БКТПБ`. `cheapClassifyHit` любое совпадение считал
`relevant`, и карточка попадала в «Закупки» с пометкой «Релевантна по
словам: КТПБ, КТП».

Модель в консольном поиске не участвует (см. `apps/agent-runtime` —
DomainSearchAgent не подключён к `apps/api`), поэтому дешёвый фильтр был
последней инстанцией.

## Решение

### `packages/domain/src/search/term-match.ts`

Добавлен `termMatchStrength(text, term): "exact" | "embedded" | "none"`.

- `exact` — целый токен, ограниченная фраза, склонение (термин ≥ 4 букв как
  префикс: «трансформатор» → «трансформаторной»), или термин в начале кода,
  за которым не идёт буква: `КТПБ-250`, `НКУ-0,4`.
- `embedded` — термин внутри кодоподобного токена, но не в его начале:
  `КТПБ` в `БКТПБ-746`, `2БКТПБ`. Это подсказка, не доказательство.
- `none` — нет совпадения. Короткие аббревиатуры по-прежнему не ищутся
  внутри обычных слов («НКУ» в «инкубатор», «КРУ» в «круглосуточной»).

Если в тексте есть и точное, и вложенное совпадение — возвращается `exact`.
Старый `termMatches` оставлен как обёртка (`!== "none"`) для адаптера и
других мест, где нужен грубый признак «есть хоть что-то».

### `packages/domain/src/search/cheap-classify.ts`

Новый вердикт `weak`: ключевых слов с точным совпадением нет, но есть
вложенные. Порядок: исключение → `irrelevant`; точное → `relevant`;
вложенное → `weak`; ничего → `ambiguous`. `matchedTerms` для `weak` содержит
именно вложенные термины, чтобы карточка могла объяснить, что нашлось.

`DomainSearchAgent` менять не пришлось: `weak` не равен ни `irrelevant`, ни
`relevant`, поэтому попадает в ветку «к модели» — то, что и требуется.

### `packages/domain/src/search/search-cards.ts`

`selectRelevantSearchCards` переписан в один проход по уникальным хитам:

- `irrelevant` — отброшен;
- `relevant` — карточка в `cards`, пока не достигнут `limit`;
- `weak` — карточка в `ambiguousCards` через `cardFromWeakHit` с текстом
  «Слова … встречаются только внутри чужого кода — проверьте по смыслу»;
- `ambiguous` — карточка в `ambiguousCards` через `cardFromAmbiguousHit`.

Ранее слабые совпадения, попадая в `listed` и не проходя `relevant`,
пропадали молча — не были ни в списке, ни во Входящих. Теперь они всегда
доходят до специалиста.

### `apps/api/src/app.ts`

`runManualSearch` больше не добавляет сомнительные (`weak` и `ambiguous`)
в `items` ответа. Они пишутся в каталог и во Входящие, как раньше, но
список после нажатия «Искать по профилю» показывает только уверенные
совпадения. Счётчик `ambiguousCount` в уведомлении сохранён.

## Что не сделано в этом этапе

- `GET /api/procurements` по-прежнему отдаёт весь накопленный каталог,
  включая сомнительные с прошлых поисков — они попадают туда через
  `catalog.procurements()`, который собирает карточки и из Входящих.
  Уборка старых карточек и признак жизненного цикла (`found` / `decided`)
  — следующий этап.
- Проверка по лотам для слабых совпадений и подключение модели к консоли
  вынесены отдельно: оба требуют дополнительного запроса к площадке на
  каждый хит, и решать, что именно грузить, лучше один раз.

## Тесты

- `term-match.test.ts`: `exact` для целого слова, фразы, склонения и
  `КТПБ-250`; `embedded` для `БКТПБ-746`, `2БКТПБ`, `БКТПБ`; `exact`
  побеждает при совместном присутствии; `none` для «инкубатор».
- `cheap-classify.test.ts`: `weak` для «БКТПБ-746»; `relevant` при
  одновременном точном и вложенном.
- `search-cards.test.ts`: «БКТПБ-746» → сомнительная с пояснением про
  чужой код, «КТПБ-250» → список; `discardedCount` не растёт.
- `app.test.ts`: `items` содержит только уверенные; сомнительные во
  Входящих.

`npm run verify` — зелёный.

## Риски

- Профиль, у которого все ключевые слова — короткие аббревиатуры, встречающиеся
  в основном внутри моделей (`КТП` в `БКТП`, `2БКТПБ`), теперь будет чаще
  отправлять карточки во Входящие. Это ожидаемо: специалист может добавить
  сами модели как отдельные ключевые слова (стартовый профиль уже содержит
  `2БКТПБ` и `БКТП`).
