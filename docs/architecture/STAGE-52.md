# Этап 52 — «Участвовать» продолжает скачивание после смены вкладки

**Статус:** решение «Участвовать» сразу пишется в кабинет. Скачивание и
индексация файлов идут на сервере и не зависят от открытой вкладки консоли.

---

## 1. Цель

После «Участвовать» специалист может уйти в «Мои закупки», входящие или
другой раздел. Раньше длинный `POST /decision` ждал весь ingest: смена
вкладки снимала панель поиска, браузер обрывал запрос, а единственный
stdio-канал MCP путался с `procurement.get` с другой карточки.

## 2. Архитектурное решение

```
POST /api/procurements/:id/decision { kind: participate }
  → triage + карточка площадки
  → persist и ответ сразу
  → ingest в фоне (тот же cabinet ALS)
  → GET /ingest-progress как раньше
  → persist документов, когда файлы готовы

stdio MCP: serializeMcpToolCaller — get и get_documents не пересекаются
консоль: SpecialistApp держит poll, пока ingest listing/downloading/indexing
```

Модель по-прежнему не ставит оценку. Числа на прогресс-баре — вес файлов
из `ingestOverallPercent`, не 0–100 закупки.

## 3. Почему именно так

Привязывать минуты скачивания к HTTP-запросу кнопки нельзя: SPA размонтирует
поиск на каждом `NavLink`. Ответ «участвуем» должен пережить disconnect.
Очередь на MCP — та же причина, что комментарий этапа 38: один stdio-процесс
не мультиплексирует инструменты.

BullMQ для этого не нужен: ingest живёт в процессе API, прогресс уже в памяти
хаба. Рестарт API по-прежнему прерывает незаконченный ingest — это тот же
риск, что у живого POST.

## 6. Контракты

`POST /decision` для participate больше не ждёт файлы: в ответе triage и
карточка площадки, `documents` может быть пустым. Готовые файлы — повторный
`GET /api/procurements/:id` или poll `GET .../ingest-progress`.

## 7. Тесты

- POST participate возвращается, пока ingest ещё `listing`
- после завершения ingest карточка в GET содержит файлы
- monitor по-прежнему не вызывает ingest
- второй MCP-вызов не стартует, пока не закончился первый
- консоль показывает прогресс в списке «Мои закупки» и на открытой карточке

## 8. Риски

- Рестарт API посреди фона теряет незаконченный ingest; повторное
  «Участвовать» запускает снова.
- Discovery/поиск ждут свободного stdio, пока качается большой ТЗ.
- Inbox action `documents` по-прежнему ждёт ingest в запросе — не эта кнопка.

- [x] «Участвовать» сохраняет решение, не дожидаясь всех файлов
- [x] смена вкладки консоли не вызывает `ingestProgress.fail`
- [x] прогресс виден в «Мои закупки» и на карточке кейса
- [x] `npm run verify` без живой площадки
