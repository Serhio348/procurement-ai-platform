# Этап 53 — у срока оплаты есть «после чего»

**Статус:** «в течение 30 календарных дней» без события, от которого
считают срок, больше не попадает в карточку. Цитата и строка условия
держат якорь из документа.

---

## 1. Цель

В ТЗ было: оплата «в течении 30 календарных дней после подписания акта
сдачи-приемки». Консоль показывала «Срок оплаты: 30 календарных дн.» и
цитату без «после чего». Специалисту нужны период, сумма и контекст.

## 2. Архитектурное решение

```
в течение N дней + сразу после в тексте «после / с даты / со дня …»
  → quote = период + якорь (дословно, до точки или запятой)
  → строка «Срок оплаты/поставки» = N дн. + тот же якорь
  → «аванс, не превышающий N%» = потолок, не точка 70%
```

Число по-прежнему считает код. Якорь не выдумывается: берётся только то,
что стоит сразу за сроком на той же странице.

## 3. Почему именно так

Этап 41 уже классифицировал «после подписания акта» как оплату, но в
цитату попадал только фрагмент «в течении N дней». Классификация видела
правый контекст, карточка — нет.

Модель может дочитать пропущенный срок; промпт просит копировать «после
чего», а в карточку по-прежнему пускает `keepTrustedClaims`.

## 4. Изменения

- `cheap-extract.ts` — якорь в quote; `не превышающий` как cap
- `detail.ts` / `reading.ts` — значение срока с якорем
- `reader-prompt.ts` — цитата срока не бывает голой
- тесты на формулировку из живого ТЗ

## 5. Изменения БД

Нет. Уже проиндексированные карточки не пересчитываются сами. На этапе 54
кнопка «Обновить» в карточке перечитывает скачанные файлы.

## 6. Тесты

- 30 дней после акта сдачи-приемки остаются в quote и в «Срок оплаты»
- «не превышающий 70%» → аванс до 70%, не ровно 70%
- поставка «с даты заключения» и оплата «с даты поставки» не теряют хвост

## 7. Критерии приёмки

- [x] срок оплаты в карточке содержит «после подписания акта», если так в ТЗ
- [x] `npm run verify` без живой площадки
