# Этап 54 — «Обновить» перечитывает скачанные файлы

**Статус:** в карточке «Мои закупки» кнопка «Обновить» по-прежнему тянет
страницу площадки. Для «Участвовать» она ещё раз разбирает уже скачанные
файлы, без повторного `get_documents` / `download`.

---

## 1. Цель

После смены экстрактора (этап 53: якорь «после чего» у срока оплаты)
старые карточки не пересчитываются сами. Специалист не должен заново
нажимать «Участвовать» и качать ТЗ с goszakupki.by.

## 2. Архитектурное решение

```
POST /api/procurements/:id/reindex
  → hydrate карточки площадки (как GET /card)
  → persist и ответ сразу
  → если triage = participate и есть hashed-файлы:
       reindex blobs (диск / MinIO) → recognize → commercial read
  → если hashed нет — тот же фоновый ingest, что у «Участвовать»
  → если monitor — только страница площадки, файлы не трогаем

консоль: «Обновить» на participate вызывает POST, не GET /card
прогресс — тот же ingest-hub, poll в SpecialistApp
```

Площадку не дёргаем за списком файлов, если хеши уже есть. Новые вложения
на странице этим нажатием не подтягиваются.

## 3. Почему именно так

Повторный download бьёт по сессии площадки и по лимиту файлов. Условия
лежат в уже сохранённых байтах; меняется только код, который их читает.
Monitor по-прежнему не качает документы — у «Отслеживать» файлы не
индексируются.

Фон тот же, что у этапа 52: HTTP-запрос кнопки не ждёт OCR. Смена вкладки
не отменяет переиндексацию.

## 6. Контракты

`POST /api/procurements/:id/reindex` отвечает списком из одной карточки,
как `POST /decision`. Документы в ответе ещё могут быть старыми; готовые
условия — повторный `GET /api/procurements/:id` или poll ingest-progress.

## 7. Тесты

- reindex не вызывает `procurement.get_documents` и `procurement.download`
- POST при hashed-файлах вызывает `reindex`, не `ingest`
- POST без hashed на participate падает в полный ingest
- monitor не вызывает ни ingest, ни reindex
- «Обновить» на карточке participate вызывает `reindex`

## 8. Риски

- Новые файлы на площадке после первого «Участвовать» этим кнопкой не
  появятся. Нужен полный ingest, если hashed-список пуст, или отдельный
  этап «докачать».
- Рестарт API посреди фона теряет незаконченный reindex — как ingest.

## 9. Критерии приёмки

- [x] «Обновить» на «Участвовать» перечитывает blobs без повторного download
- [x] «Отслеживать» по-прежнему только страница площадки
- [x] `npm run verify` без живой площадки
