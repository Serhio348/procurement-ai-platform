# Этап 56 — поиск по кнопке без минуты ожидания

**Статус:** кнопка «Поиск» больше не ждёт дочитывания карточек и не
листает шесть страниц выдачи на каждый объект. Оценка 0–100 и порог
discard / match / review не менялись.

---

## 1. Цель

После этапов 48–51 выдача стала чище, но один прогон занимал 1–2 минуты.
Специалист ждал не скорер, а очередь HTTP к goszakupki.by.

## 2. Архитектурное решение

```
кнопка «Поиск»
  → план модели ∥ listing (дешёвые objects, ≤4 фразы, ≤2 страницы/фраза)
  → scoreSearchIntent по готовому плану (как этапы 48–51)
  → match сразу в список
  → review без procurement.get → входящие

фон discovery
  → listing с тем же капом фраз/страниц
  → сомнительные: карточка, затем модель (как этап 34)
```

Лимит `100` в запросе консоли — сколько **релевантных** строк оставить
после скорера, а не сколько сырых строк скачать с площадки.

## 3. Почему именно так

Адаптер ходит на площадку не чаще 20 раз в минуту (~3 с между GET).
Старый расчёт страниц `ceil((offset+limit)/20)+1` при `limit: 100` давал
**6 страниц на объект**. Пять objects — это уже минута только на список.
Разбор сомнительных добавлял до 50 `procurement.get` в ту же очередь и
в тот же stdio MCP — ещё минута.

Скорер дешёвый и его не трогаем: мусор по-прежнему отбрасывается кодом.
Дочитать лот («в спецификации есть насос») можно ночью; на нажатии
кнопки это не стоит 50 карточек.

Дешёвый план и ответ модели почти всегда называют те же objects, поэтому
listing стартует, не дожидаясь DeepSeek. Оценка всё равно идёт по плану
модели, когда он готов.

## 6. Контракты

HTTP API тот же. `POST /api/procurements/search` чаще отдаёт сомнительные
во входящие без пометки «карточка решила», потому что карточки на кнопке
больше не открываются.

## 7. Тесты

- `limit: 100` на listing с «далее» запрашивает не больше двух страниц
- кнопка поиска не вызывает review-порт; инкубатор discard, «Поставка
  НКУ» ждёт во входящих
- listing стартует, пока план модели ещё заблокирован
- discovery по-прежнему повышает hit по лоту и не спрашивает повторно
- `platformSearchTerms(..., 4)` отрезает хвост, без лимита — все objects

## 8. Риски

- Редкий синоним пятым object на кнопке не уйдёт на площадку. Кап — 4
  первых из плана.
- Пока идёт ingest «Участвовать», поиск всё ещё стоит в одной stdio-
  очереди MCP (этап 52). Это отдельный этап, не эта правка.
- «Ещё» в консоли почти не появится: сырых строк после двух страниц
  обычно меньше 100, `hasMore` ложно.
