# Этап 65 — профиль поставки не принимает работы за найденные

## Цель

Площадка ищет по словам профиля (`КТП`, `подстанция`) и возвращает в том
числе реконструкцию, строительство и подряд. Оценка считала «оборудование
есть, слова поставка нет → значит поставка» и клала такие карточки в
«Закупки» как найденные.

Нужно: для профиля поставки голова заголовка про работы — вето, не
совпадение. Слова профиля по-прежнему уходят на площадку; меняется только
вердикт после карточки.

## Архитектурное решение

Числа `SEARCH_INTENT_WEIGHTS` не трогаем. Меняется распознавание предмета.

1. `purchaseWorkHead` смотрит первые значащие слова заголовка: услуги,
   работы, реконструкция, строительство, прокладка, подряд, субподряд,
   СМР, модернизация, демонтаж. Не добавляем эти слова в
   `excluded_actions` целиком — иначе «Поставка КТП для реконструкции»
   получила бы вето из середины фразы.

2. Для `equipment_purchase` `scoreSearchIntentFromProcedure` оценивает
   заголовок и каждый лот отдельно:

   - смешанный лот «монтаж …, поставка …» → по-прежнему review;
   - лот сам говорит «поставка / изготовление» объекта → match;
   - иначе работа в заголовке или в лоте → veto;
   - иначе неявная поставка по названию оборудования.

3. Ведущая клауза режется и по переводу строки: предмет лота не подменяет
   голову заголовка процедуры.

Отброшенные работы не пишутся в кабинет. Они видны в «Почему не взяли» и
в логе `Specialist search card scored` / `skipped`.

## Тесты

- реконструкция / строительство / прокладка / подряд по профилю КТП → veto;
- «Реконструкция котельной» + лот «НКУ» → veto;
- тот же заголовок + лот «Поставка НКУ» → match;
- «КТП 400 кВА» и «Поставка КТП с услугами шефмонтажа» → по-прежнему match;
- смешанный лот → review.

## Риски

- «Модернизация КТП» без слова поставка станет вето. Если это закупка
  нового изделия — лот должен назвать поставку.
- «Устройство» как существительное НКУ не считаем работой; «устройство
  сетей» ловим отдельной фразой.
