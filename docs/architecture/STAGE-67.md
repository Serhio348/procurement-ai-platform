# Этап 67 — уже взятый аукцион не пропадает из «Почему не взяли»

## Цель

По «КТПБ» площадка отдаёт две строки: живой аукцион и завершённый
маркетинг. Завершённую платформа честно отсекает по статусу. Аукцион
`auction/3664806` уже был в «Участвовать», снова находился поиском,
получал `relevant`, но вкладка «Закупки» скрывает watched/participate —
в итоге в UI оставалась только одна видимая процедура (отсев), а вторая
как будто «не попала».

## Архитектурное решение

1. Retrieval и listing не менялись: адаптер по-прежнему отдаёт обе строки.
2. В `collectPendingHits` карточка с triage `participate` / `monitor`
   больше не уходит на повторный `procurement.get`. Она сразу попадает в
   `skipped` с причиной «уже в „Мои закупки“».
3. Отклонённые и ранее разобранные как irrelevant тоже пишут причину в
   тот же список, чтобы «Почему не взяли» совпадал с числом строк площадки.

## Почему так

Очередь поиска не должна дублировать «Мои закупки». Но молчаливый пропуск
уже взятой строки выглядит как потеря retrieval. Специалист должен видеть
обе строки сайта: одну — как статусный отсев, вторую — как уже взятую.

- `apps/api/src/app.ts` — `collectPendingHits` + запись в progress.skipped
- `apps/api/src/app.test.ts` — регрессия: participate + completed
