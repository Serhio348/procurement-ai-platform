# Этап 68 — универсальный отсев работ по предмету профиля

## Цель

Во «Входящих» копился общестрой по словам «СМР» / «пусконаладка» без предмета
профиля. Нельзя зашивать «энергетику» в код: платформа универсальна. Предмет
задаёт профиль; модель читает профиль целиком.

## Решение

1. **Код (works):** если в тексте нет объектов/`required_context` профиля и
   совпали только общие фразы работ (СМР, подряд, пусконаладка…) — **veto**,
   без модели. Если есть специфичная фраза профиля без объекта — **review**
   (модель).
2. **Модель:** relevant только по смыслу *этого* профиля (keywords/objects),
   не из‑за голых «СМР».
3. **UI профиля:** подсказка при фокусе на названии; поле «Для модели
   (направление)» пишется в `description` и уходит классификатору.
4. **«Исключать»** — только стоп-слова площадки, не промпт.

## Дополнение: запросы на площадку и desired (A+C)

1. **`platformSearchTerms` (works):** не отправляет на площадку голые СМР / монтаж /
   пусконаладка / подряд; объекты плана по-прежнему запрашиваются **отдельными**
   запросами.
2. **`inferSearchIntentPlan` / merge:** в `desired_actions` не попадают голые глаголы
   работ и чисто generic-фразы — только сохранённые фразы с предметом (если специалист
   сам так сохранил). Голый глагол из фразы больше не дублируется в desired.
3. **Скоринг:** если объект профиля есть в заголовке, а desired пуст, код всё равно
   видит сигнал работ в тексте (монтаж / СМР / …) — match без склейки keywords.

**Не склеивать.** Keywords держите раздельно: «система очистки воды», «водоподготовка»,
«электрооборудование». На площадку уходит каждый предмет своим запросом. Голые
«монтаж» / «СМР» / «пусконаладка» не уходят. Склейка в одну фразу не нужна и вредна:
пропадают закупки материалов и оборудования.
