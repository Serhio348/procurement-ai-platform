# Этап 70 — «На проверку» открывается туда, где карточку видно

## Цель

Во входящих у строки «На проверку» кнопка «Открыть карточку» снимала
сообщение, но во вкладке «Закупки» карточка не появлялась. Специалист
терял закупку из поля зрения.

## Почему так выходило

1. «Открыть» всегда вело на `/procurements/:id` (список поиска).
2. Если по этому же `sourceProcurementId` уже было решение «Слежу» /
   «Участвую», `withTriage` снова вешал triage на карточку.
3. Вкладка «Закупки» намеренно скрывает watched/rejected. Карточка
   оказывалась и не во входящих, и не в списке поиска.
4. Повторный поиск мог снова положить уже решённый review во входящие
   (`restoreReviewInbox`), и цикл повторялся.

## Архитектурное решение

1. Решённый источник (`decidedSourceIds`) больше не ставится во входящие
   как «На проверку»: ни при restore, ни через `queueFoundInbox`.
2. «Открыть» для undecided по-прежнему поднимает `foundAs: match` и
   кладёт id в очередь поиска профиля.
3. Для уже watched/rejected «Открыть» не возвращает карточку в очередь
   поиска.
4. Консоль после «Открыть» ведёт:
   - undecided → «Закупки»;
   - monitor/participate → «Мои закупки»;
   - reject → «Корзина».

## Тесты

- поиск не возвращает monitored review во входящие;
- open по stale «На проверку» с triage monitor отдаёт карточку в
  `tab=monitor`, не в `tab=search`;
- UI после open watched review открывает «Мои закупки».

## Критерии приёмки

- «На проверку» без решения → «Открыть» → карточка в «Закупках».
- «На проверку» по уже отслеживаемой → «Открыть» → карточка в
  «Моих закупках», входящие пустеют.
- Повторный поиск не поднимает решённую закупку снова как «На проверку».
