# Этап 76 — Удаление профиля: крестик и быстрый persist

## Цель

Крестик «×» на списке профилей должен сразу удалять лишний профиль.
Раньше удаление ждало полный `persist()` кабинета (все карточки) и при
ошибке UI молчал — казалось, что крестик «не работает».

## Решение

1. **API:** create / save / activate / watch / delete профиля пишут только
   состояние workspace (`persistWorkspaceOnly`), без перезаписи всех case
   card. Профиль — строка в `workspace_profiles`, карточки закупок к нему
   не привязаны FK.
2. **UI:** крестик показывает «…» на время запроса, ловит ошибку в toast,
   `stopPropagation`, подсказка если профиль один.

## Почему так

Полный `saveCabinet` на каждое изменение профиля вставал в ту же очередь,
что и поиск. DELETE мог висеть секунды без индикатора — специалист жал ×
повторно и думал, что кнопка мёртвая.

## Критерии приёмки

- При двух и более профилях × удаляет выбранный и обновляет список.
- Единственный профиль: × disabled, видна подсказка.
- Ошибка удаления показывается toast'ом, а не глотается.
- `npm test` для ProfileList и API profile-сценариев зелёный.

## Дополнение

`persistWorkspaceOnly` пишет через `saveWorkspaceMeta`: только профили, active id
и очередь поиска. Вердикты чужих профилей, решения, архив и inbox не
переписываются. UI убирает строку сразу, а при ошибке API возвращает её.
