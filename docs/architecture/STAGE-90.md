# Этап 90 — модель видит то же, что scorer: релевантные цитаты лотов вместо первых N названий (R14)

Детерминированный scorer читает title, все лоты, их описания и позиции
(`scoreSearchIntentFromProcedure`). Классификатор получал только первые
восемь названий лотов и первые двенадцать raw fields — объект,
сработавший в позиции или девятом лоте, исчезал ровно на семантической
проверке. Этап отдаёт модели тот же предмет, который видел код.

## Что изменилось

`SearchClassifierInput.card` расширился двумя полями:

- `lotExcerpts: [{number, text}]` — полный текст лота (название +
  описание + позиции, как в `lotIntentText`), до 600 символов на лот;
- `lotCount` — полное число лотов на карточке, чтобы модель видела
  факт усечения, а не «тихий» срез первых восьми.

Per-lot скоринг вынесен из `scoreIntentProcedure` в экспортируемый
`scoreIntentLots` — тот же `scoreSearchIntent` по `lotIntentText` в той
же стабильной сортировке (`number`, затем текст). Вердикт карточки и
выбор цитат для модели считаются **одним кодом**, поэтому R07
(независимость решения от порядка лотов) сохранён конструктивно, а не
только тестом.

`classifierCardProjection(card, plan?)` в `search/review.ts` — общая
проекция для обоих call site:

- с планом — впереди лоты, реально сработавшие на объекте, целевом
  действии, исключении или контексте (matchedObjects / matchedDesired /
  excludedActions / matchedContext не пусты), дальше — остальные по
  порядку до `CLASSIFIER_LOT_EXCERPT_LIMIT` (8);
- без плана (agent-runtime `projectCard`) — первые лоты целиком с
  `lotCount`: модель всё равно видит описания и позиции, а не голые
  названия.

`buildSearchClassifierInput` и `projectCard` в domain-search agent зовут
эту проекцию — две реализации «что видит модель» больше не существует.

## Ограничения

- Excerpt-лимит — 8 лотов; карточки с большим числом сработавших лотов
  отдают первые восемь по релевантному порядку, `lotCount` сигналит об
  остальном.
- Лоты, сработавшие только на исключённом контексте (`contextRole` —
  агрегат без per-lot разметки), не цитируются отдельно: veto-вердикт
  и так не доходит до модели.
- Per-lot скоринг считается дважды на неразрешённой карточке (вердикт +
  проекция) — CPU без лишних model calls; при необходимости можно
  пробросить уже посчитанные lot scores в `buildSearchClassifierInput`.

## Регрессии

- `review.test.ts`: объект в девятом лоте попадает в `lotExcerpts` с
  `lotCount=9`; объект только в позиции лота доходит до модели; набор
  цитат идентичен при обратном порядке лотов (R07/R14).
- Существующие `intent-score.test.ts` (4 параметризованных порядка) и
  `search-review.test.ts` («in either lot order», без вызова модели) —
  зелёные без правок, что и есть доказательство семантической
  идентичности рефактора.
