# Этап 92 — pending-фраза профиля не теряется при сохранении (R29)

В `ProfileApp` текст поля «Добавить слово» не входил ни в `currentWrite()`,
ни в `dirty`. Специалист мог вписать терм и сразу нажать «Сохранить профиль»
или «Следить» без Enter — фраза молча пропадала из поиска, а если это было
единственное изменение, даже предупреждение не показывалось.

## Что изменилось

`splitPhrases` (разбор по запятым/переводам строк) и `mergePhrases`
(дедупликация без учёта регистра) — общие хелперы; `addQueries` и
`currentWrite()` теперь используют их одинаково:

- `effectiveKeywords()` = чипы + pending-ввод `addWord`;
- `currentWrite().keywords` отправляет оба источника — Save и Watch не
  теряют фразу;
- `dirty` вычисляется из того же `currentWrite()`, поэтому набранный терм
  сам по себе считается изменением: баннер «несохранённые изменения»,
  подтверждение по ссылке «Все профили» и `beforeunload` покрывают его
  автоматически. Pending-ввод, который лишь повторяет существующий чип
  (в другом регистре), изменением не считается.

После успешного сохранения или переключения слежения локальные `keywords`
синхронизируются с ответом сервера, `addWord` очищается — фраза появляется
чипом, форма перестаёт быть dirty.

## Границы

- R30 (навигационные guard'ы меню/Back и сброс формы при смене профиля) —
  отдельный пункт; здесь покрыт только сигнал `dirty` для pending-ввода.
