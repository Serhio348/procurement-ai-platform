# STAGE-93 · Защита несохранённых правок и сброс формы профиля (R30)

## Проблема

- Предупреждение «есть несохранённые изменения» срабатывало только при закрытии
  вкладки (`beforeunload`) и по ссылке «Все профили». Переход по боковому меню
  терял правки молча.
- Маршрут `/profiles/:id` переиспользовал один экземпляр `ProfileApp`: при
  прямом переходе профиль A→B локальные `useState` сохраняли поля A, а
  `save` уже писал под `id` профиля B.

## Решение

- `apps/web/src/shell/UnsavedGuard.tsx` — контекст с `confirmLeave()` и
  `setBlocker()`. Провайдер стоит внутри `BrowserRouter` поверх `Routes`
  в `SpecialistApp`, поэтому любой будущий dirty-экран покрывается без
  правок шелла.
- `ProfileApp` вызывает `useUnsavedChanges(dirty, UNSAVED_PROMPT)` — пока
  форма грязная, зарегистрирован `window.confirm`-блокер; при очистке он
  снимается.
- `Shell` навешивает `useGuardedClick()` на все `NavLink` меню — клик при
  грязной форме спрашивает и при отказе делает `preventDefault`.
- `ProfileEditorRoute` передаёт `key={profile.id}` — смена `:id` монтирует
  форму заново, поля не утекают между профилями.

## Ограничение

Кнопки Back/Forward браузера в декларативном `<BrowserRouter>` честно не
перехватываются (`useBlocker` работает только в data-роутерах
`createBrowserRouter`). Покрытие сейчас: боковое меню, ссылка «Все профили»,
закрытие/перезагрузка вкладки. Полное покрытие Back — миграция на
data-router, отдельной задачей.

## Регрессии

- `ProfileApp.test.tsx`: dirty + клик по «Входящие» → confirm и навигация
  блокируется; подтверждение → уход; чистая форма → уход без вопроса;
  смена `:id` → поля нового профиля, черновик A не попадает в B.
