# STAGE-95 · «Открыть карточку» ведёт туда, где живёт кейс (R48)

## Проблема

`InboxRoute.onResolve` на действие `"open"` всегда навигировал на
`/procurements/:id` — вкладку поиска. У отслеживаемого кейса там нет полной
карточки: `sourceCard` и документы хранятся в кабинете и рендерятся в
«Мои закупки». Пользователь нажимал «Открыть карточку» по событию
«Обновлён документ» и видел пустую поисковую карточку.

## Решение

`inboxOpenTarget(card)` в `SpecialistApp.tsx` выбирает раздел по состоянию:

| Состояние кейса            | Цель                    |
|----------------------------|-------------------------|
| `triage === "reject"`      | `/trash/:id`            |
| `monitor`/`participate`/`archived` | `/my-procurements/:id` |
| кандидат без решения       | `/procurements/:id`     |

Карточка по-прежнему сначала запоминается через `showInSearchPane` →
`rememberCard`, поэтому detail-страница рендерит её без дополнительного
запроса.

## Регрессии

- `SpecialistApp.storage.test.tsx`: событие по `monitor`-карточке →
  «Открыть карточку» → активна навигация «Мои закупки», не «Закупки».
  Существующий кейс неразобранного кандидата (`match`, без triage) продолжает
  открываться в «Закупки».
