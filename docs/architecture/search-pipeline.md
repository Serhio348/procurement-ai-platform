# Как работает поиск по профилю

Документ описывает конвейер поиска закупок так, как он реализован в коде
(этапы 20–30). Правила детерминированные — без «похоже/не похоже».

## Схема конвейера

```
Профиль («Что ищем» + правки + исключения + статусы)
        │
        ▼
searchPhrasesFromLookingFor — фразы целиком, длинные не режутся
        │
        ▼
Каждая фраза — отдельный запрос к площадке (TendersSearch[text]),
до 30 страниц на фразу, offset для «Загрузить ещё»
        │
        ▼
Адаптер goszakupki.by — мягкий пред-фильтр (сырая подстрока ключевого
слова в заголовке/заказчике/статусе). Исключения здесь НЕ применяются.
        │
        ▼
Домен — строгие ворота по порядку:
  1. дедуп по sourceId:sourceProcurementId
  2. статус процедуры (hitMatchesProfileStatuses)
  3. запрещённые слова (cheapClassifyHit → exclusions)
  4. ключевые слова (termMatches)
        │
        ├─ совпало ──► карточка «релевантна по словам: …» → список
        ├─ исключено/статус не тот ──► отброшено
        └─ ничего не совпало ──► СОМНИТЕЛЬНАЯ ──► карточка
             «проверьте по смыслу» + запись во «Входящих»
```

## Ворота подробно

### 1. Дедуп
Одинаковый `sourceId:sourceProcurementId` встречается один раз, даже если
закупка пришла по нескольким запросам.

### 2. Статус
- `profile.statuses` пуст → фильтра нет.
- Статус распознан и не входит в список → отброшена.
- Статус не распознан / отсутствует в строке → проходит (нет данных ≠
  завершена).
- По умолчанию профиль смотрит только `accepting_bids` («Приём
  предложений»).

### 3. Запрещённые слова
Любое слово из «Исключать», сматчившееся по правилам `termMatches`, сразу
убивает хит — даже если ключевое слово тоже совпало. Исключение выше всего.
Отклонённые ранее карточки (`rejectedSourceIds`) не возвращаются ни в
список, ни во «Входящие».

### 4. Ключевые слова — `termMatches`
Текст = `title + buyerName + sourceStatus`. Токен — непрерывная
последовательность букв/цифр/`-`/`/`.

Одно слово совпадает, если хотя бы одно из трёх:

1. **Токен равен слову**: `НКУ` в «устройство НКУ».
2. **Префикс токена** — только для слов ≥4 букв (склонение):
   `трансформатор` → «трансформаторной». Короткие аббревиатуры (НКУ, КРУ,
   КТП — 2–3 буквы) префиксом не считаются: «круглосуточной» ≠ КРУ.
3. **Внутри кодового токена** — токен содержит цифру/дефис/слэш или весь в
   верхнем регистре: `КТПБ` в «2БКТПБ», «БКТПБ-746», «БКТПБ». Внутри
   обычного слова — нет: `НКУ` в «банку» не считается.

Многословный термин («сетей электроснабжения») — фраза целиком с границами
слова по краям: «комплект сетей электроснабжения» — да,
«сетей электроснабжениями» — нет.

## Что куда попадает

| Исход | Условие | Куда |
|---|---|---|
| relevant | слово совпало, исключений нет | список «Закупки» |
| irrelevant | исключение сматчилось | отброшена |
| отброшена | статус не из списка | отброшена |
| ambiguous | пришла, не выбита, не совпала | карточка + «Входящие», до 50 за прогон |

`discardedCount` в ответе = все хиты минус карточки и сомнительные.

## Сомнительные во «Входящих»

Сомнительная становится карточкой (иначе её нельзя открыть и решить) и
получает запись `procedure_found` во «Входящих». `change.id`
детерминирован → повторный поиск не дублирует записи. В навигации у
«Входящих» — бейдж с числом, после поиска обновляется сразу.

## Запасной путь для модели (будущий этап)

Сомнительные — то самое место, где встанет модель: она получит только
пограничные хиты (не весь сайт: строка без подстроки слова вообще не приходит
с площадки). Вердикты: «ваше» → в список с пометкой «отобрано моделью»,
«не ваше» → отброшена, «не уверена» → во «Входящие» человеку. Бюджет
`DomainSearchAgent` — 50 классификаций за прогон. Без LLM-ключа поведение
не меняется: сомнительные идут человеку.

Для покрытия закупок «по смыслу без слов» планируется поле профиля
«смысловые понятия» — отдельные запросы к площадке, чьи результаты идут
только через модель/человека, никогда не попадают в список напрямую.

## Лимиты

- `SpecialistSearchRequest`: `limit` ≤ 500 (дефолт 100), `offset` ≥ 0.
- `SearchQuery.limit` ≤ 500; адаптер — до 30 страниц на фразу (20 строк на
  страницу).
- «Загрузить ещё» в консоли шагает `offset += 100`, пока `hasMore`.
- Фоновое слежение использует тот же конвейер (offset 0).
